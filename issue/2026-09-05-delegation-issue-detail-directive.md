### 요구 4 의 버전 — 원천이 디스크에 없다. 두 후보를 다 확인해서 둘 다 죽었다

이것이 이번 항목의 핵심 판단이라 근거를 다 적는다.

**후보 1 — 프론트매터 버전 필드.** 없다. 83 개 카드 어디에도 `version` 계열 키가 없다.

**후보 2 — git 히스토리.** `lion_work` 는 큐를 `.gitignore` 의 `/*` 로 무시한다. 큐 폴더 자체는

```
$ cd lion-work-queue
$ git log --oneline | wc -l                        →  3      (커밋 3 개)
$ git ls-files 'inbox/*.md' 'done/*.md' | wc -l    →  63     (83 중 20 개는 추적조차 안 됨)
$ 카드별 리비전 수                                   →  82 개가 1, 1 개가 2
```

git 을 버전 원천으로 쓰면 화면에 82 개가 `v1`, 1 개가 `v2`, 20 개가 `버전 없음` 으로 찍힌다.
쓸모가 없다.

**후보 3 — 계보 필드.** `preceding:` 1 개, `folded_into:` 1 개, `folded_date:` 1 개,
`discovered_from:` 1 개. 실재하지만 4 개 카드뿐이다.

### 그래서 버전 원천을 이렇게 정한다 — 이것이 이번 항목의 가정이다

> **버전의 원천은 컨디션 메이트가 스스로 쌓는 관측 원장이다.** 디스크에는 없다.

앱이 `/issues` 를 열 때마다 카드 본문을 해시해서 자기 데이터 폴더에 원장으로 남긴다.
해시가 이전과 다르면 새 버전이다. 버전 N = 지금까지 관측한 서로 다른 해시의 수이고, 가장
최근 것이 마지막 버전이다.

- 저장 위치: **`AppPaths.sub("work-queue")/versions.json`.** 큐 폴더도 아니고
  `AppPaths.sub("issue")` 도 아니다.

  > **2026-09-05 22:48 정정.** 이 문서의 앞선 판은 원장을 `AppPaths.sub("issue")` 에 두라고
  > 적고 있었다. 그것은 틀렸다. 그 경로는 `IssuePaths.root` 이고 **goal 저장소**다 —
  > `ls -d ~/.condition-mate/issue/goal-* | wc -l` → **155**. goal 폴더 155 개와 첨부와
  > goal 별 chat 이 사는 자리에 큐 원장을 떨어뜨리면 goal 저장소를 오염시킨다.
  > `IssuePaths` 는 이번 일과 아무 상관이 없다. 읽지도 고치지도 마라.
- 첫 스캔은 83 개를 전부 `v1` 로 심는다. 화면에는 그냥 `v1` 이 아니라
  **`v1 · 2026-09-05 첫 관측`** 이라고 쓴다. 없는 역사를 있는 척하지 않는 것이 이 화면의 값이다.
- 이후 라이언이 말해서 카드가 고쳐지면 해시가 바뀌고 `v2` 가 되며, 무엇이 바뀐 버전인지
  관측 시각과 함께 쌓인다.
- `preceding:` / `folded_into:` / `discovered_from:` 가 있는 4 개 카드는 그 링크를
  **`이전 버전` / `다음 버전`** 으로 같이 그린다. 수는 적지만 진짜 데이터다.

**왜 이 안인가.** 라이언의 말은 "내가 계속 이야기하면서 버전 업이 되고" 다 — 즉 버전은
*앞으로* 대화하면서 올라가는 것이다. 과거 83 개의 없는 역사를 만들어 내는 것이 요구가 아니다.
오늘부터 정직하게 세기 시작하면 요구가 충족되고, 오늘 화면은 "전부 v1, 오늘 처음 봄" 이라고
사실대로 말한다. 대안(카드 슬러그 유사도로 계보를 추측)은 근거가 없는 추측을 화면에 사실처럼
올리는 것이라 이 화면의 유일한 목적 — 라이언이 믿고 창을 안 여는 것 — 을 정면으로 깬다.

### 요구 2 의 "수정된 최초의 리퀘스트" — `## 원문` 은 절대 못 건드린다

`QUEUE.md` 2026-09-05 14:31 기록:

> 카드 규칙 위반(**원문 훼손**, 프론트매터 target·handle 채움, 구조 위반)으로 폐기되고 재작성.

카드 하나가 원문 훼손으로 폐기된 적이 실제로 있다. 그러므로 "수정된 최초의 리퀘스트" 는
`## 원문` 을 고친 것일 수 없고 **원문 옆에 따로 서는 값**이어야 한다.

디스크에 이미 있는 것: `## 1초 요약` 의 `요구` 줄이다. 그것이 정확히 "보이스로 엉망으로
들어간 원문을 사람이 읽을 수 있게 고친 한 줄" 이다. 다만 커버리지가 완전하지 않다.

```
$ ## 1초 요약 이 없는 카드  →  18 개 (전부 8/25~9/03 의 옛 카드)
   2026-08-25-1919-developer-vs-gtm-owner-essay 외 17 개
```

그래서 **떨어지는 순서를 정한다.**

1. `## 정리된 요청` 절이 카드에 있으면 그것 (지금은 0 개. 앞으로 큐 PO 가 쓸 수 있게 자리를 연다)
2. 없으면 `## 1초 요약` 의 `요구` 줄 (65 개)
3. 없으면 **`(정리 안 됨)` 이라고 쓰고 원문 앞부분을 보인다** (18 개)

3 번을 빈칸으로 두지 마라. "정리 안 됨" 은 라이언이 이 카드를 정리해야 한다는 정보이고,
빈칸은 화면이 고장 났다는 신호다. 둘은 다르다.

### 4. `/api/issues/reveal` — Finder 열기 (POST)

> **먼저 확인한 것.** 상위 세션이 "`/api/settings/issue-folder/reveal` 이 이미 있으니 재사용할
> 수 있는지 봐라" 고 했다. **찾아보니 없다.** 실측:
> ```

> 7422:  if path == "/api/settings/issue-folder" {
> 7425:  if path == "/api/settings/issue-folder/pick" {
> ```
> `reveal` 은 없다. 존재하는 reveal 엔드포인트는 셋뿐이다 — `/api/settings/reveal`(7145,
> `data`/`bgm`/`claude` 세 값 고정), `/api/skills/reveal`(7385), `/api/agents/reveal`(7390).
> 재사용할 것이 없으므로 새로 만든다. L1 이라 되묻지 않고 확인해서 진행했다.

**보안 규칙을 그대로 따른다.** 이 저장소는 임의 경로 열기를 한 번도 허용한 적이 없다.
`/api/settings/reveal` 조차 세 개짜리 고정 열거값만 받고 호출자가 준 경로는 절대 안 받는다
(7142-7144 주석). `AppDelegate.swift:6185-6194` 의 `revealAgentPath` 가 본보기다.

```swift
guard p.hasSuffix(".md"), !p.contains(".."), knownAgentPaths().contains(p) else {
    return "{\"ok\":false,\"error\":\"unknown-path\"}"
}
```

**핵심은 `knownAgentPaths().contains(p)` — 허용 목록 대조다.** 새 엔드포인트도 똑같이,
"이번 스캔에서 카드로부터 실제로 파싱해 낸 경로 집합" 안에 있을 때만 연다. 그 밖의 경로는
`unknown-path` 로 거절한다. 웹뷰에서 온 문자열을 그대로 `activateFileViewerSelecting` 에
넘기면 대시보드가 임의 파일 열람 통로가 된다.
