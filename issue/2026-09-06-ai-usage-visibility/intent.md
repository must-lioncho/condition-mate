# AI 사용량을 한곳에서 확인하려는 의도

작성일: 2026-09-06 · 버전: I2 · 상태: 사용자 우선순위 정정 반영, 나머지 해석은 확인 전

## 가장 중요한 의도

컨디션 메이트에서 여러 AI 서비스의 사용량을 사진처럼 한눈에 확인하고 싶다. 특히 사진에서 사용량이 나오지 않는 Antigravity와 지원되지 않는 GLM도 같은 인터페이스에서 볼 수 있어야 한다.

원하는 결과를 먼저 보존한다. 문제 정의가 틀릴 수 있고 솔루션은 여러 개일 수 있으므로, 하나의 문제 정의나 구현 방식이 이 의도를 대신하지 않는다.

## 우선순위에 관한 명시적 의도

Antigravity와 GLM의 실제 지원 가능성을 먼저 확인한다. 이 불확실성을 남겨 둔 채 기존에 제공되던 Claude·OpenAI 쪽에 먼저 집중하면, 핵심 요구를 충족하지 못하는 작업에 자원을 쓸 수 있다.

문제 정의에는 문제 목록뿐 아니라 **우선순위, 그 순서의 이유, 다음 단계로 넘어갈 근거**를 포함한다. 구현하기 쉬운 순서보다, 결과에 따라 후속 작업을 바꾸거나 불필요하게 만들 수 있는 불확실성을 먼저 확인한다.

이번 정정은 검토 순서를 확정한 것이다. 원래 요청한 문서 작성 범위는 유지하며, 실제 지원 가능성은 아직 검증하지 않았다.

## 이번에 요청한 범위

1. 의도를 문서로 남긴다.
2. 의도를 바탕으로 문제 정의 초안을 만든다.
3. 가능한 솔루션들을 비교 가능한 후보로 남긴다.

이번 작업의 완료는 위 문서들이 만들어진 상태다. 기능 구현, 연결 실험, 인증 설정, 배포, 최종 솔루션 선택은 이번 범위에 포함하지 않는다.

## 아직 의도로 확정하지 않은 해석

- 사진의 사용률과 리셋 표시로 보아, 핵심은 누적 토큰보다 **계정의 한도 대비 사용률과 초기화 시점**일 가능성이 높다.
- ‘똑같은 인터페이스’는 우선 **짧은 요약 표시 → 펼쳐서 서비스별 상세 확인**이라는 구조로 해석한다. 픽셀 단위 복제나 최종 배치 위치는 확정하지 않았다.
- 어떤 AI를 이어서 사용할지 판단하려는 목적이 있을 수 있지만, 자동 계정 전환이나 모델 추천을 요청한 것은 아니다.
- 사진의 Claude·Codex·Gemini를 함께 보여주는 것을 후보 범위로 삼되, Gemini 오류 수리까지 요청했다고 해석하지 않는다.
- GLM의 어떤 상품·계정·한도인지, Antigravity의 어떤 계정·모델 그룹인지 아직 특정하지 않았다.

## 의도와 버전 관리

현재: 의도 I2 → [문제 정의 P2](problem-v2.md) → [솔루션 후보 S2](solutions-v2.md).

이전: [I1](intent-v1.md) → [P1](problem-v1.md) → [S1](solutions-v1.md).

문제 정의를 바꿀 때는 `problem-v2.md`처럼 새 버전을 만들고 새 근거, 이전 정의가 부족했던 이유, 현재 의도와의 관계를 쓴다. 솔루션도 `solutions-v2.md`처럼 별도로 버전업하고 기반 문제 버전을 적는다. 문제와 솔루션의 버전은 함께 올릴 필요가 없다.

의도는 기술 제약에 맞춰 몰래 축소하지 않는다. 사용자가 의도를 정정하거나 확장할 때 버전을 올리고 이전 내용과 변경 이유를 남긴다. 후보의 탈락도 의도의 포기를 의미하지 않는다.

## 변경 이력

- I1: 최초 의도 기록.
- I2: 사용자 정정에 따라 Antigravity·GLM 지원 가능성 확인을 최우선으로 명시. 문제별 우선순위와 선행 조건을 필수로 추가. 핵심 사용량 표시 목표와 문서 작성 범위는 유지.
