# 솔루션 후보 v1 — 무엇이 무엇을 소유하는가

기반 의도 [`intent.md`](intent.md) (I1) · 기반 문제 [`problem-v1.md`](problem-v1.md) (v1) · 2026-09-07

## 두 값이 답하는 질문은 다르다

이것이 후보를 가르는 축이다.

| 값 | 답하는 질문 | 성질 |
|---|---|---|
| `WorkQueueStore.root` (큐 폴더) | **카드가 어디 쌓여 있나** | 사용자가 고른다. 오늘 선택기가 실렸다 |
| `WorkQueueStore.lionWorkRoot` (워크스페이스 루트) | **`organization/` 트리가 어디 있나** | 사용자가 고른 적 없다. 이 맥에 하나뿐이다 |

두 값 사이에 **불변식이 없다.** 옛 배치에서 큐는 `<root>/organization/lion/lion-work-queue` 였고
새 배치에서는 `<root>/queue` 다. 둘 다 루트 아래지만 **깊이가 다르다.** 지금 코드는 옛 배치의
깊이를 규칙으로 못박은 것이고, 그것이 P1 의 실체다.

## 후보

### S1 — 지금처럼 큐에서 루트를 되짚되 규칙을 늘린다

`FAST` 자식이 넣기로 한 최소 방어(마지막 조각이 `queue` 면 부모)의 확장판이다.

- 해결하는 문제 — P2 만.
- 의도 기여 — 오늘 화면이 다시 돈다.
- 전제 — 사용자가 고르는 큐 폴더의 이름이 앞으로도 `queue` 이거나 경로에 `/organization/` 이 있다.
- 기대 효과 — 한 줄. 가장 싸다.
- **탈락 조건에 걸렸다.** 카드의 `완성` 줄이 "임의 폴더를 골라도 … lion_work 루트를 가리키며"
  라고 적고 있다. S1 은 `~/Desktop/scratch` 를 고르는 순간 루트를 `~/Desktop/scratch` 로 옮긴다.
  **P3 를 원리적으로 못 고친다.**
- 더 나쁜 것 — 검증할 수 없다. "이 문자열 규칙이 앞으로의 선택을 덮는다" 를 단언할 수 있는
  시험을 쓸 수 없다. 규칙을 늘릴수록 다음에 깨질 자리만 늘어난다.
- **채택 안 함.** 다만 `FAST` 자식이 임시로 넣는 것은 막지 않는다 — 그것은 오늘 도는 앱을 위한
  방어이고, S4 가 들어가면 **동작이 진부분집합이라 그대로 대체된다.**

### S2 — `lion_work` 루트를 별도 설정으로 두고 큐 폴더를 그 아래에서 되짚는다

의존 방향을 뒤집는다.

- 해결하는 문제 — P2·P3.
- 전제 — 큐가 항상 루트 아래에 있다.
- **탈락.** 의존이 사라지지 않고 방향만 바뀐다. 그리고 오늘 실린 선택기를 망친다 — 루트 밖
  폴더(`/tmp/fixture`)를 고르는 것이 정당한 격리 용도인데 S2 는 그것을 거부해야 한다.
  사용자가 실제로 만지는 값(큐 폴더)을 만지지 않는 값(루트)의 종속물로 만드는 것도 거꾸로다.

### S3 — 둘을 서로 독립된 설정 두 개로 두고 각각 기본값을 준다

- 해결하는 문제 — P2·P3.
- 전제 — 사용자가 두 값을 각각 맞게 유지한다.
- **탈락.** 소유 관계는 맞는데 **비용을 사용자에게 넘긴다.** 화면에 틀릴 수 있는 값이 하나 더
  생기고, 둘이 어긋났을 때 앱이 알려 줄 방법이 없다. 격리 시험도 환경변수 하나에서 둘로 늘어
  `CM_WORK_QUEUE_DIR` 만 넣고 산출물이 실제 디스크를 가리키는 사고(원래 주석이 막으려던 바로 그것)가
  오히려 쉬워진다. 사용자가 워크스페이스 루트 UI 를 요청한 적도 없다.

### S4 — **채택.** 루트가 자기를 소유하고, 큐 경로는 루트를 *찾는 힌트*일 뿐 루트가 *되지는* 않는다

`lionWorkRoot` 의 출처를 이 순서로 둔다.

1. `CM_LION_WORK_DIR` — 있으면 그것. **지금과 같다.** 격리의 명시적 탈출구이고 이미 있다.
2. 큐 경로에서 **위로 올라가며** `organization/` 디렉터리를 **디스크에서 실제로 가진** 첫 조상을
   돌려준다 (큐 폴더 자신부터 본다).
3. 못 찾으면 **자기 기본 상수** `/Users/lioncho/Work/lion_work`. **큐 폴더 자신으로 떨어지지 않는다.**

- 해결하는 문제 — **P1·P2·P3** 를 한 번에.
- 의도 기여 — 카드의 `완성` 줄 그대로다. 임의 폴더를 골라도 루트가 안 따라간다(3단계).
- 무엇이 달라졌나 — 2단계가 **문자열 자르기를 디스크 표식 찾기로 바꾼다.** 한 규칙이 옛 배치
  (`<root>/organization/lion/lion-work-queue` → `<root>`)와 새 배치(`<root>/queue` → `<root>`)를
  **둘 다** 맞춘다. 깊이를 몰라도 된다. 이것이 S1 과의 진짜 차이다 — S1 은 깊이를 안다고 가정하고
  S4 는 표식을 찾는다.
- **소유 판정이 들어 있는 자리는 3단계다.** 힌트가 아무것도 못 찾았을 때 루트가 움직이지 않는다는
  것, 그것이 "루트가 자기를 소유한다" 의 코드 표현이다.
- 관측된 사실 — 옛 배치와 새 배치 둘 다 루트 아래에 `organization/` 이 있다. 실측으로
  `/Users/lioncho/Work/lion_work/organization/` 이 존재한다.
- **설계 가설 (관측 아님)** — 앞으로도 워크스페이스 루트의 표식은 `organization/` 이다.
  이 맥의 배치 규약(`lion_work/organization/<조직>/workspace/<프로젝트>`)이 근거지만,
  규약이 바뀌면 표식도 바뀐다. SPEC 에 그 전제를 적어 둔다.

#### 의식적으로 되돌리는 가정 하나

지금의 `return root` 폴백은 주석상 "픽스처 안에서 상대경로가 픽스처 안으로 풀리게" 하려는 것이다.
S4 는 그 폴백을 없앤다. **그렇게 고른 이유:**

- `organization/` 을 가진 픽스처는 2단계가 그대로 잡는다. 잃는 것은 **`organization/` 이 없는**
  픽스처 하나뿐이고, 그 경우는 `CM_LION_WORK_DIR` 하나로 해결된다.
- 실측(O10) 상 `CM_WORK_QUEUE_DIR` 를 설정하는 **자동 러너가 하나도 없다.** 그 폴백이 지키는
  상황은 오늘 아무도 밟지 않는다.
- 반대쪽은 오늘 실렸다. 폴더 선택기가 있으므로 "임의 폴더" 는 가설이 아니라 **클릭 한 번**이다.
- 즉 **드문 경우를 위해 흔한 경우를 깨는 폴백**을 흔한 경우 쪽으로 뒤집는 것이다.

#### 필요한 확인

- `organization/x` 가 `/Users/lioncho/Work/lion_work/organization/x` 로 푼다.
- 큐가 `/tmp/anything` 일 때 `lionWorkRoot` 가 `/Users/lioncho/Work/lion_work` 다.
- 옛 경로(`…/organization/lion/lion-work-queue`)를 넣어도 `/Users/lioncho/Work/lion_work` 다.
- `CM_LION_WORK_DIR` 가 여전히 전부를 이긴다.

#### 제약과 유지 부담

2단계가 파일시스템을 만진다. `resolve()` 는 카드마다 포인터마다 불리므로(166 장) 매번 stat 하면
낭비다. **큐 경로를 키로 한 메모이제이션이 필요하다** — 상수 캐시는 안 된다. 사용자가 도는 중에
큐 폴더를 바꿀 수 있기 때문이다(선택기가 오늘 실렸다).

## 조합 — S4 와 함께 가는 것

이 둘은 S4 의 대안이 아니라 S4 를 지키는 것들이다.

- **A. 꺼진 게이트를 켠다 (P4).** `.e2e/issues.test.js:594-595` 의 옛 경로 폴백을 새 경로로
  바꾼다. 지금 라이브 큐 블록이 통째로 건너뛰어지고 있다 — 이걸 안 고치면 S4 가 다음에 조용히
  되돌아가도 아무도 모른다.
- **B. SPEC 항목을 세운다 (P5).** `DASH-15`. 최대가 `DASH-14` 라 다음 번호이고, 접두사는 이
  계약이 `/issues` 화면의 포인터와 Orca 버튼을 지배하므로 `DASH` 계열이 맞다.

## 선택 상태

**S4 채택. 확정.** 핵심 불확실성(P1)이 남아 있지 않다 — 카드의 `완성` 줄이 S1·S2 를 배제하고,
실측 O10 이 S4 가 되돌리는 가정의 비용을 0 에 가깝게 만든다. 그래서 조건부가 아니라 확정으로 적는다.

미검증 전제로 남는 것은 하나다 — **`organization/` 이 앞으로도 루트의 표식이다.** SPEC 에 적는다.
