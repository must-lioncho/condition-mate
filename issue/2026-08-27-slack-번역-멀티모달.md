# Slack 번역 멀티모달 확장

상태: 제안

Condition Mate 대시보드의 `Slack 번역` 탭이 텍스트뿐 아니라 이미지, PDF, 영상, YouTube, 인용 블록까지 근거로 삼아 번역·의미 분석·의사결정을 만들도록 확장한다.

현재 `items.jsonl` 1251건을 전수 조사해 미처리 및 저품질 유형과 실제 수치를 확인하고, 확인된 모든 유형을 함께 개선한다. 첨부만 있는 메시지를 버리지 않도록 수집 경로를 보완하고, Slack의 `files`, `attachments`, `blocks`, 인용 및 스레드 원문을 하위 호환되는 optional 필드로 다룬다. PDF는 텍스트 레이어를 먼저 추출하고 비어 있으면 OCR/비전으로 폴백하며, 영상은 프레임 단위로 분석하고 YouTube는 자막과 요약을 활용한다.

`items.jsonl`은 데몬만 쓰게 유지하고 스키마 변경 전 백업하며 기존 1251줄을 그대로 읽을 수 있어야 한다. API 키는 키체인에서만 읽고 기록하지 않는다. 외부 Slack 쓰기나 리액션은 하지 않으며, 이미지·영상 원본 등 외부 모델로 전달되는 데이터와 목적지를 최종 보고에 명시한다.

작업은 직접 구현하지 않고 데이터 분석, 수집, 멀티모달 파이프라인, 인용·서식, UI, QA 축의 워커 서브에이전트로 병렬 수행한다. 빌드와 실행 검증은 QA 워커가 `Scripts/build-app.sh`와 관련 E2E를 사용해 담당한다. 최종 보고에는 전수 분석 수치, 유형별 수정 내역(파일과 줄), 검증 결과를 담는다. 요청 없이 커밋하거나 푸시하지 않는다.

## 분류 코멘트

목적지는 `organization/lion/lion-condition-mate`다. 산출물이 Condition Mate의 Slack 번역 기능 구현과 검증이기 때문이다. 가까운 후보는 없으며, 큐 자체의 규칙 변경이 아니므로 `organization/lion/lion-work-queue`는 대상이 아니다. 출처 id는 `2026-08-27-1330-slack-translate-multimodal`이다.

## 착수 준비 (2026-08-27 director 런에서 확정된 것)

### 확정된 사실 — 다시 조사하지 말 것

`slack-eyes-daemon.mjs` 에는 `files`, `url_private`, `mimetype` 이라는 문자열이 **한 번도 나오지 않는다**
(grep 결과 0건). 그러므로 데몬은 슬랙 첨부 파일을 인지하는 경로 자체가 없다. 최초 지시문에 적혀 있던
"`:218-219` 에서 attachments 와 blocks 를 이미 보존하고 있다" 는 items 경로에 대해서는 **사실이 아니다**.
그 두 줄은 채널 구독(channel-subscription) 디스패치 payload 를 만드는 다른 기능의 코드이고,
items.jsonl 레코드를 만드는 자리는 대략 `:838-868` 이며 거기에는 attachments 도 blocks 도 없다.

첨부만 있고 본문이 빈 메시지는 `:808-813` 에서 `error: 'empty-text'` 로 버려진다.

`translateGemini` 는 `:635-652` 이고 `contents: [{ parts: [{ text: prompt }] }]` 하나만 보낸다.
멀티모달 파트를 넣을 자리가 구조적으로 없다.

### 베이스라인 (변경 전 실측, QA 워커)

빌드는 성공한다 (`bash Scripts/build-app.sh --stage`, 65초, Slack 관련 경고 0건).
`node --check` 통과. 대시보드 헤더 실측값은 `미처리 135 · 전체 1256` (`GET /api/slack/items`).

`npm run test:slack` 은 **이번 작업 이전부터 이미 깨져 있다**. `slackretrig.test.js` 가
`ReferenceError: act is not defined` 로 죽고(`&&` 체인이라) 뒤의 세 개가 실행조차 안 된다.
원인은 데몬의 `retrigger()` 가 `act(...)` 를 부르게 바뀌었는데 테스트 스텁에 `act` 가 없는 소스/테스트 drift다.
따라서 회귀 판정은 반드시 **개별 파일로 따로 돌려서** 비교한다. 단독 실행 시 slackhealth, slackmenu,
slackextract 세 개는 통과한다.

데몬 stdout 로그는 `/tmp/cm-slack-eyes.out.log` 이고 현재 프로세스 수명(약 2일 13시간) 동안
skip 은 `empty text (file/attachment only?)` 9건이 전부다. 더 긴 이력은 `actions-daemon.jsonl` 에 있다.

**재빌드해도 도는 데몬은 새 코드로 갈아타지 않는다.** `SlackDaemonInstall.swift:104-126` 의
`ensureInstalled()` 는 plist 의 `ProgramArguments` 가 바뀔 때만 재시작하는데 스크립트 경로는 늘 같으므로,
`.mjs` 내용만 바뀐 재설치는 조기 리턴한다. 라이브 검증 전에 반드시 대시보드의 "다시 연결" 을 누르거나
`launchctl kickstart -k gui/$(id -u)/com.condition-mate.slack-eyes` 를 수동 실행해야 한다.

### 담당 분할 — 파일 충돌이 나지 않도록 소유자를 하나씩 고정한다

`lion-condition-mate-worker-slack-corpus-analyst` 는 읽기 전용 전수 조사만 한다.
`lion-condition-mate-worker-slack-daemon` 이 `slack-eyes-daemon.mjs` 를 단독 소유한다.

### 모듈 인터페이스 계약 — 두 워커가 협상하지 않고 병렬로 일하기 위한 고정 규격

새 모듈 `Sources/Plugins/Slack/Daemon/media-extract.mjs` 는 두 가지를 내보낸다.

`collectRefs(msg)` 는 동기 함수로, 원본 슬랙 메시지 객체를 받아 참조 배열을 돌려준다. `files[]` 항목과
본문·attachments·blocks 안의 URL 을 긁어모은다. 부작용이 없어야 한다.

`extractEvidence(refs, opts)` 는 비동기 함수로, `evidence` 와 `notes` 두 속성을 가진 객체를 돌려준다.
참조 하나는 kind 가 'file' 이면 url 과 mimetype 과 name 과 size 를, 'link' 이면 url 을 가진다.
opts 는 slackToken 과 geminiKey 와 geminiModel 과 cacheDir 과 timeoutMs 를 가진다.
evidence 의 원소 하나는 ref 와, image·pdf·video·youtube·link·audio·unknown 중 하나인 type 과,
프롬프트에 그대로 넣을 수 있는 text 와, 비전 모델에 직접 넘길 파트 배열인 inline(각 원소는 mimeType 과 dataB64)과,
실제로 근거를 만들어낸 기법 이름인 method 와, 실패했을 때만 채워지는 error 를 가진다.
`extractEvidence` 는 절대 예외를 밖으로 던지지 않는다. 첨부 하나가 실패해도 메시지 전체가 깨지면 안 된다.

### items.jsonl 새 필드 — optional 로만 추가하고 기존 줄은 그대로 읽혀야 한다

`media` 는 선택 배열이고 원소는 type 과 name 과 url 과 method 와 text 와 error 를 가진다.
`mediaAt` 은 선택 정수 타임스탬프다. 그 외 기존 필드는 건드리지 않는다.
UI 는 이 두 필드가 없는 옛 레코드에서도 깨지지 않아야 한다.

### 이 맥에서 실제로 쓸 수 있는 도구 (실측)

`pdftotext`, `pdftoppm`, `pdfimages`, `ffmpeg`, `ffprobe`, `sips`, `qlmanage` 가 있고
`gsk` 는 `/Users/lioncho/.local/bin/gsk` 에 있다.
`tesseract` 와 `yt-dlp` 는 **없다**. 그러므로 스캔본 PDF 의 OCR 폴백은 tesseract 가 아니라
`pdftoppm` 으로 래스터화한 뒤 비전 모델에 넘기는 경로로 만든다.
