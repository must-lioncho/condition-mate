목표 검색 — 번호 조회 기획 프로토타입

검색 모달의 검색 버튼을 "AI 유사도 검색(큐)"에서 goal 번호 즉시 조회로 재정의한다. 번호가 어디에 있든 — 활성 보드·스프린트·완료·릴리즈됨(스프린트 커밋)·보관(아카이브)·취소 — 상태와 무관하게 찾아서 보여주고, 상태에 맞는 다시 열기 액션을 제공한다. AI 유사도 검색은 별도 버튼(AI검색)으로 분리해 그대로 유지한다.

AS-IS 현재 동작

  • 1검색 버튼 = goalSearchFind() → /api/goal/queue/enqueue {search:true} — AI추가와 같은 큐 파이프라인, findOnly로 생성만 스킵.
  • 2결과는 비동기 — 큐 탭에 '검색 결과' 카드가 뜰 때까지 기다려야 한다.
  • 3텍스트 유사도 기반이라 "346" 같은 번호 입력은 의미가 없다 — 번호를 아는데도 못 찾는다.
  • 4릴리즈됨·보관된 목표는 활성 목록에서 숨어 있어 보드 어디서도 다시 볼 수 없다.

TO-BE 제안

  • 1검색 버튼 = 로컬 즉시 조회. 숫자 입력 → seq 정확 일치. 텍스트 입력 → 제목 부분일치 목록. 서버 왕복 없이 /data.json의 전체 goal(릴리즈·보관 포함)에서 찾는다.
  • 2AI검색 버튼(기존 검색 버튼의 역할) = 큐 파이프라인 그대로 — "비슷한 걸 AI가 찾아줘".
  • 3결과 카드에 상태 배지 + 현재 위치(스프린트/릴리즈 코드/보관함/큐)를 보여준다. 상세는 기존 /goal?n=346 링크 재사용.
  • 4상태별 다시 열기 액션 — 완료 해제, 보관 해제, 릴리즈에서 꺼내기, 취소 복원 (아래 매핑 표).
  • 5검색 모드에서 Enter = 검색(즉시 조회). AI검색은 명시적으로 버튼을 눌러야 한다.

결정사항 — 2026-07-09 구현 반영됨

1. 릴리즈된 목표의 개별 재오픈과 Release 기록 — 결정: 기록 불변 + 재오픈 주석
신규 POST /api/goal/reopen + ReviewStore.reopenGoal(id:) 구현. Release 기록(goalIds·titles·value)은 불변으로 남고, 릴리즈 로그가 "released가 풀린 goal"을 역산해 헤더에 n건 재오픈, 행에 ↩ 재오픈됨을 표시한다. 목표가 속한 스프린트가 이미 닫혔으면 백로그(sprint 0)로 내려 보드에서 보이게 한다.
2. 완료 해제 시 completedAt — 결정: 기존 규칙 유지(지움)
코드에 이미 확립된 정책이 있었다: done을 떠나는 순간 completedAt을 지워 "재오픈된 목표가 낡은 완료 시각을 달고 다니지 않게" 한다(stampCompletion). 프로토타입의 '보존' 제안 대신 기존 정책을 따른다. 릴리즈 기록의 releasedAt은 불변이므로 이력은 릴리즈 로그에 남는다.
3. 근접 후보 — 채택
없는 번호를 검색하면 가장 가까운 번호 3개를 칩으로 제안, 클릭 시 그 번호로 재검색.
4. 텍스트 로컬 검색과 AI검색의 경계 — 힌트 문구로 안내
검색 모드 힌트: 번호=즉시 정확 일치, 텍스트=제목 부분일치, 표현이 다르면 AI검색. 텍스트 미스 시에도 AI검색을 제안한다.
5. /goal?n= 상세 페이지의 커버리지 — 확인 완료(전 상태 렌더)
서버의 goalPage()는 reviewStore.goals 전체에서 seq로 찾으므로 릴리즈·보관·취소 목표도 상세가 열린다. 검색 결과 카드의 '상세 보기'가 그대로 링크한다.
6. 검색 모드 버튼 라벨 — [AI검색] 리라벨 + [추가] 숨김
검색 모드에서 AI추가→AI검색(findOnly 큐 파이프라인 동일), 혼란을 주는 '추가' 버튼은 숨긴다. Enter=검색(즉시 조회).
+ 덤으로 고친 버그
reviewJSON()이 releaseId를 직렬화하지 않아 아카이브 뷰의 릴리즈 날짜·복원 버튼이 항상 죽어 있었다(클라이언트가 relById[g.releaseId]를 참조하는데 필드가 없음). 직렬화에 추가해 함께 수리.

구현 참조 (AS-IS 코드)

검색 모달
DashboardContent.swift — openGoalAdd({search:true}), gaSearch() → goalSearchFind() → /api/goal/queue/enqueue {search:true}(findOnly). TO-BE는 gaSearch()를 로컬 조회로 교체하고 gaAi()가 search 모드에서 findOnly 큐 흐름을 담당.
상태 모델

번호 규칙
