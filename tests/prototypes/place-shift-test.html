장소이동 = 컨디션 관리 CONCEPT TEST

BGM 전환을 "곡 바꾸기"가 아니라 가상 장소로 이동하기로 프레이밍하면, 소리·분위기 전환이 실제 장소를 옮긴 것 같은 컨디션 회복 효과를 낸다는 가설의 테스트 페이지입니다.
예: 저녁 야근 전 밥만 먹고 오면 식곤증으로 처지지만, 라운지에 다녀오면 컨디션이 산다 — 이 차이를 앱 안에서 재현하는 게 목표.

1장소 이동 UX

카드를 누르면 그 장소로 "이동"합니다. 🔊 소리 켜기를 누르면 장소마다 다른 앰비언스가 실제로 재생됩니다(프로시저럴 생성, 음원 파일 불필요 — 기존 venue 엔진의 crowd/wind/room 방식과 동일 계열).

지금은 내 자리에 있습니다. 다른 장소를 눌러 이동해 보세요.

2컨디션 게이지 반응 (가속 시뮬레이션)

▶ 를 누르면 1초 = 시뮬레이션 10분. 자리에서 일하면 컨디션이 서서히 닳고, 장소를 이동하면 그 장소의 회복/소모 프로필이 게이지(메뉴바 5단계 번개와 동일 스케일)에 반영됩니다. 같은 장소에 오래 머물면 회복 효율이 떨어집니다(체감 모델).

3야근 저녁 시나리오 비교

동일한 18:00→23:30 야근을 세 가지 저녁 루틴으로 보냈을 때의 컨디션 곡선 비교(모형 가정치). 사용자가 실제로 겪는 "밥 먹고 오면 지친다 vs 라운지 가면 산다"를 수치 모델로 옮긴 것.

A. 밥만 먹고 복귀 (식곤증) B. 라운지 + 가벼운 식사 C. 쉼 없음
모델상 23:30 시점 컨디션: B안이 A안보다 약 2배 높게 유지됩니다. 핵심 차이는 ① 식곤증 급락 회피, ② 21시경 짧은 재이동(옥상 5분)으로 하락 기울기를 한 번 더 꺾는 것. → 앱이 줄 수 있는 가치: 야근 감지 시 "라운지로 이동할까요?" 제안 + 가상 장소 앰비언스로 실제 이동 없이 그 효과의 일부를 재현.

4통합 옵션 — 어디까지 갈 것인가

테스트 페이지에서 확인한 요소(장소 카드 UX, 앰비언스 전환, 컨디션 반영)를 본 앱에 넣는 3단계 옵션. 각 옵션은 이전 옵션을 포함합니다.

LEVEL 1 — 리프레이밍
🪑 프리셋을 "업무 장소"로 교체
  • 기존 venue 프리셋(콘서트홀/클럽…)을 라운지·카페·옥상·심야서재 세트로 확장/교체
  • PRESETS 정의 + amb 프로필만 추가 — 엔진 변경 없음
  • UI 문구를 "이동하기"로 변경
변경 범위: BGMPlayerContent.swift PRESETS 블록만 · 리스크 최소 · 컨디션 게이지와 무관
추천 시작점
LEVEL 2 — 장소이동 UX
🚶 이동 행위 + 체류 기록
  • "이동" 트랜지션(앰비언스 크로스페이드 + 배너) 도입
  • 체류 시간 추적 → 컨디션맵 24h 띠에 장소 색 오버레이
  • 장소 방문 이력을 activity 이벤트로 기록 (기존 스토어 재사용)
변경 범위: BGMPlayerContent + 컨디션맵 탭 + 이벤트 스키마 1개 · 게이지는 아직 표시만
LEVEL 3 — 컨디션 루프
⚡ 게이지 반영 + 야근 제안
  • 장소 체류가 메뉴바 5단계 번개 게이지에 실제 반영(회복 모델)
  • 야근 감지(기존 6h갭 업무시작 로직 응용) 시 "라운지 다녀오기" 제안
  • 회복 모델 파라미터는 이 테스트 페이지 값에서 시작
변경 범위: 게이지 계산 파이프라인 + 알림 · 모델 검증 필요 → 2를 먼저 쓰면서 데이터 축적 후 진행

※ 이 페이지의 회복/소모 수치는 전부 가정치(모형)입니다. 목적은 정확한 예측이 아니라 ① 장소이동 프레이밍이 체감상 설득력 있는지, ② 앰비언스 전환만으로 "이동한 느낌"이 나는지, ③ 어느 레벨까지 구현할지 결정하는 것. 판단 기준 제안: 소리를 켜고 장소를 2~3번 옮겨봤을 때 "곡을 바꿨다"가 아니라 "자리를 옮겼다"로 느껴지면 LEVEL 2 진행.
