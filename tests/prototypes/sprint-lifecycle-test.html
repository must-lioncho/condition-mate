확인된 문제 (AS-IS)

P1 · Complete sprint가 무조건 후속 스프린트를 생성
completeSprint(ReviewStore.swift:1142)가 이월할 목표가 없어도 항상 새 1d 스프린트를 만든다. 빈 스프린트를 완료해도 또 빈 스프린트가 생겨 같은 날짜에 계속 쌓인다.
P2 · 복원해도 완료 시 생긴 후속 스프린트가 남음
복원은 릴리즈 삭제 + 원 스프린트 재오픈만 한다. 후속(빈) 스프린트는 그대로 → 복원→재완료를 반복하면 26-15…26-23처럼 증식.
P3 · 부분 재커밋이 연도 채번을 소모 → 번호 갭
nextReleaseCode가 두 번째 커밋에 새 YY-n을 발급하고, maxYearCode가 릴리즈 코드까지 스캔하므로 보드에서 26-19 같은 번호가 건너뛰어진 것처럼 보인다.
P4 · 코드(별칭)·날짜를 정리할 UI 부재
code는 자동 채번뿐, 어디서도 수정 불가. 자동화가 만든 어색한 번호/날짜를 손볼 방법이 없다.
P5 · 완료 로그의 제목 클릭이 펼치기와 겹치고, 기간을 기록·수정할 수 없음
완료된 스프린트는 완료 시각(releasedAt)만 남는다. 하루 2회 스프린트, 2일에 1회 스프린트처럼 실제 기간이 다양해도 표현할 수 없고, 제목 클릭은 펼치기/닫기에 묶여 있어 편집 진입점도 없다.

제안 정책 (TO-BE)

R1 · 후속 스프린트는 "이월할 목표가 있을 때만"
완료 시 미완료 목표가 없으면 그냥 닫는다(생성 없음). 미완료가 있으면: 이미 열린 다른 스프린트가 있으면 그중 가장 이른 것으로 이월(재사용), 없을 때만 새로 생성(auto 표시).
R2 · 빈 스프린트 완료 = 기록 없이 닫기
목표 0개·결과물 없음이면 릴리즈 기록도 남기지 않고 닫기만 한다.
R3 · 복원 = 완료의 완전한 되돌리기
릴리즈에 carriedTo/carriedIds를 기록해 두고, 복원 시 이월됐던 목표를 원 스프린트로 되돌린다. 완료가 자동 생성한 후속 스프린트가 그로 인해 비면 함께 삭제.
R4 · 부분 재커밋 코드 = "26-15.2" 접미사
두 번째 이후 커밋은 새 채번을 소모하지 않고 스프린트 코드에 .2 .3을 붙인다. 번호 갭 소멸, 로그 유일성 유지.
R5 · 번호(pill) 클릭 → 상세 설정 모달
별칭(code)과 시작/목표 일시를 직접 편집. 별칭은 스프린트+릴리즈 코드 전체에서 유일해야 저장된다. TO-BE 보드에서 pill을 직접 클릭해 보세요.
R6 · 기존 데이터 정리 (1회성)
열린 빈 스프린트(목표 0·결과물 없음)가 여러 개면 정리: 비어있지 않은 열린 스프린트가 있으면 빈 것 전부 삭제, 없으면 최신 1개만 유지. POST /api/sprint/cleanup + 보드 버튼으로 제공.
R7 · 완료 로그: ▸=펼치기, 제목 클릭=제목·기간 편집
릴리즈가 스프린트의 시작 일시를 스냅샷(startedAt)하고, 완료 일시(releasedAt)와 함께 편집 가능. 하루 2회·2일 1회처럼 실제 기간을 사실대로 기록한다. 별칭도 같은 모달에서 수정(전체 코드 유일성 검증). 펼치기/닫기는 앞의 ▸ 버튼으로 분리.
