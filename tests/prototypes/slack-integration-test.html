권장
🪝 Incoming Webhook

Slack이 발급한 고정 URL 하나에 POST만 하면 지정된 채널에 메시지가 뜹니다. 단방향(보내기 전용).

●만료: 없음 (재발급 불필요)
●스코프/권한: 최소 (채널 1개 쓰기)
●기능: 보내기만 · 읽기/버튼 없음
●설정: 앱 만들고 URL 복사
🤖 Bot Token (rotation OFF)

Slack 앱의 xoxb- 봇 토큰. 토큰 로테이션을 끄면 만료되지 않습니다. 여러 채널·읽기·업데이트 가능.

●만료: 없음 (로테이션 OFF일 때)
●스코프: 지정 권한만 (chat:write 등)
●기능: 보내기+읽기+수정+버튼
●설정: OAuth 설치 필요
🔁 OAuth + Token Rotation

access 토큰이 12시간마다 만료, refresh 토큰으로 자동 갱신. 보안 최고지만 바로 그 재발급 로직이 필요.

●만료: 12시간 · 자동 refresh 구현 필수
●스코프: 지정 권한만 · 유출 시 피해 최소
●기능: 전체
●설정: refresh 스케줄러 필요 (복잡)
※ 걱정하신 “expire되면 재발급” 이슈는 3번(Rotation)에서만 발생합니다. 1·2번은 만료 자체가 없어 재발급 로직이 필요 없습니다.

    6 · 걱정거리 정면 답변
    토큰이 만료되면 매번 재발급해야 하나?
    해결 Webhook 또는 rotation-OFF 봇토큰이면 만료 없음. Rotation 방식만 골라야 재발급 로직이 필요 — 그건 안 고르면 됨.
    토큰이 코드/깃에 노출될까?
    해결 Keychain 저장 + 웹뷰로 값 미반환 + .gitignore. 대시보드 GET 화이트리스트에 secret 엔드포인트 추가 금지.
    토큰이 유출되면 피해 범위는?
    완화 Webhook=해당 채널 쓰기만. 봇=부여한 스코프만. 유출 시 Slack에서 revoke 후 1개만 재발급.
    로컬 앱인데 굳이 OAuth 서버가 필요한가?
    불필요 Webhook/봇토큰은 서버·콜백 URL 없이 붙여넣기만으로 동작. Rotation만 리다이렉트 처리가 필요.
    보내기만 vs 양방향?
    선택 알림만이면 Webhook으로 충분. 나중에 버튼/응답/여러 채널이 필요해지면 봇토큰으로 승급.
    최종 제안 요약
    1단계 (지금): Incoming Webhook + macOS Keychain 저장. 만료·재발급 이슈 원천 제거, 30분이면 붙음.
    2단계 (필요 시): 버튼·양방향·다채널이 필요해지면 Bot Token(rotation OFF)로 승급 — 여전히 만료 없음.
    회피: Token Rotation은 “보안 최상”이지만 바로 그 재발급 부담을 만들므로, 규정상 강제되지 않는 한 채택하지 않음.
    이 페이지에서 방식·트리거·메시지 모양을 확정하시면, 실제 Swift 연동 스펙으로 넘기겠습니다.
