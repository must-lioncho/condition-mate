# Zen 창 시작/중단 펄럭임(flap) — 유저 테스트 시나리오

범위: 레일의 챌린지 다이얼(시작/중단)과 zen 창 접힘/펼침의 동기화. 2026-08-07 Loom 녹화
2건("Condition Manager - 대시보드 - 7 August 2026")에서 확인된 문제를 고정한다. 시나리오는
실제 소스(SessionRail.swift)에서 함수를 추출해 구동하는 `zenflap.test.js` 로 자동 검증되며,
아래의 수동 시나리오는 릴리즈 전 눈으로 한 번 더 확인할 때 쓴다.

## 배경 — 녹화에서 확인된 문제

챌린지 시작/중단 버튼은 즉각 반응(낙관적 갱신)하고, 실제 상태는 2초 주기의
`/api/session/state` 폴로 재확인한다. 그런데 클릭 순간 이미 날아가 있던(또는 서버 반영
전에 돌아온) 폴이 "이전 상태"를 보고하면, 렌더러의 zen 엣지가 방금 편 창을 도로 접거나
접은 창을 도로 펴 버렸다.

로그 근거 (app.log, KST):

- 14:22:32.068 zen expand → 14:22:33.202 zen re-narrow → 14:22:35.151 zen expand
  (시작 클릭 후 약 3초간 검은 화면 — 녹화 2 의 02:08:18~02:08:22 구간)
- 14:22:50.763 zen expand → 14:22:50.776 zen re-narrow (13ms 간격 — 클릭 시점에 이미
  날아가 있던 폴이 착지) → 14:22:54.401 zen expand (녹화 1 의 02:08:40~02:08:42 구간)

사용자에게 보이는 증상:

- 시작을 눌렀는데 창이 펴졌다 → 도로 접혔다 → 다시 펴진다 (펄럭임)
- 그 사이 보드 영역이 수 초간 검은 빈 화면으로 노출된다 (cm-zen 이 보드를 숨긴 채
  창만 넓은 상태)
- 이전 세션의 시계/모드가 폴에 실려 와 새로 고른 모드·0초 시계를 잠깐 덮어쓸 수 있다

수정: 낙관적 시작/중단 래치 (`cmChPendWant` / `cmChPendUntil`). 클릭한 상태를 서버가
폴로 되돌려줄 때까지(최대 8초) 유지하고, 그 사이 반대 상태의 폴은 무시한다. 래치 중의
스테일 폴은 시계(`cmChSecs`/`cmChWall`)와 모드도 덮어쓰지 못한다. 컨트롤 POST 가
돌아오면 즉시 재폴링해 래치를 최대한 빨리 푼다. 8초가 지나도록 확인이 없으면 서버
말이 맞다고 보고(시작이 실제로 실패한 경우) 조용히 실제 상태로 돌아간다.

## 시나리오 1: 시작 클릭 — 창은 한 번만 펴진다

목적: 시작 직후의 스테일 폴이 창을 도로 접지 않는다.

- Given 챌린지가 멈춰 있고 창이 레일 폭(242pt)으로 접혀 있다
- When 다이얼(챌린지 시작)을 클릭한다
- Then 창이 즉시 펴지고 보드가 나타난다
- And 이후 2~4초 안에 창이 다시 접히거나 검은 화면이 보이지 않는다
- And 다이얼은 계속 실행 상태(정지 버튼·시계 진행)를 유지한다

## 시나리오 2: 스테일 폴은 시계·모드도 못 덮는다

목적: 이전 세션의 잔재가 새 세션의 표시를 오염시키지 않는다.

- Given 직전 세션이 스프린트 모드로 돌았고, 지금은 포모도로를 골라 시작했다
- When 시작 직후 이전 상태(스프린트, 잔여 시계)를 실은 폴이 도착한다
- Then 다이얼은 포모도로 25:00 부터 정상 카운트다운한다 (잔여 시계로 튀지 않는다)
- And 모드 라벨이 스프린트로 바뀌지 않는다

## 시나리오 3: 중단 클릭 — 창은 한 번만 접힌다

목적: 중단 직후의 스테일 실행중 폴이 창을 도로 펴지 않는다.

- Given 챌린지가 실행 중이고 창이 펴져 있다
- When 다이얼(챌린지 중단)을 클릭한다
- Then 창이 레일 폭으로 접힌다
- And 이후 접힌 창이 저절로 다시 펴지지 않는다

## 시나리오 4: 래치는 클릭 창구만 지킨다 — 외부 중단은 그대로 접힌다

목적: 래치가 폴을 영구히 무력화하지 않는다.

- Given 시작이 서버까지 확인된 뒤(래치 해제) 세션이 실행 중이다
- When 다른 경로(⌘S, 메뉴, 포모도로 완주)로 세션이 멈춘다
- Then 다음 폴에서 창이 정상적으로 접힌다 (수확 오브면 수확 화면으로)

## 시나리오 5: 시작이 실제로 실패하면 조용히 되돌아간다

목적: 실패 배너 없이(no-user-facing-failure) 현실로 복귀한다.

- Given 시작 클릭 후 서버가 8초가 지나도록 실행 상태를 보고하지 않는다
- Then 다이얼이 멈춤 상태로 돌아가고 창이 레일 폭으로 접힌다
- And 오류 배너는 띄우지 않는다

## 자동화 매핑

`node .e2e/zenflap.test.js` 가 시나리오 1~5 를 소스 추출 함수로 검증한다:
시작 클릭 → expand 1회, 스테일 폴 무시(창·cmChRun·시계·모드), 확인 폴 → 래치 해제,
래치 해제 후 외부 중단 → narrow, 중단 클릭 → narrow 1회 + 스테일 실행중 폴 무시,
래치 만료 → 서버 상태 수용. 수동 확인은 위 시나리오 1·3 을 실제 앱에서 한 번씩
눌러 보는 것으로 충분하다 (검은 화면·펄럭임이 보이면 회귀).
