# 슬랙 답변 정책 — 색인

이 폴더는 슬랙 자동 답변이 **무엇을 읽고 무엇을 남길지**를 정한 정책 묶음이다. 한 덩어리로
두지 않고 레벨별로 쪼갠 이유는 하나다 — 답변 프로세스가 커지면서 정책을 에이전트 정의 안에
넣으면 에이전트가 그 무게로 무너지기 때문이다. 그래서 정책을 파일로 빼고, 부르는 쪽이
**필요한 하나만 열게** 했다.

## 여는 순서 — 이것이 이 폴더의 전부다

1. `router.md` 를 **먼저** 읽는다. 예외가 없다.
2. 라우터가 두 가지를 판정한다 — 이모지(의사결정이 필요한가)와 레벨(L0~L5).
3. 판정된 레벨의 파일 **하나만** 연다.

**전부 읽지 않는다.** 여섯 개를 다 열면 이 폴더를 쪼갠 이유가 사라진다.

## 무엇이 있는가

| 파일 | 무엇 | 언제 여는가 |
|---|---|---|
| `router.md` | 이모지 판정 → 레벨 판정. 판정 규칙만 있고 행동은 없다 | **언제나. 맨 먼저.** |
| `level-0.md` | 읽지 않는다. 리액션 하나로 끝낸다 | 라우터가 L0 으로 판정했을 때 |
| `level-1.md` | 단문만 읽는다. 슬랙 API 0회 | 라우터가 L1 으로 판정했을 때 |
| `level-2.md` | 스레드를 통으로 읽는다. **오늘의 기본값** | 라우터가 L2 로 판정했을 때 |
| `level-3.md` | 스레드 밖 · 회사 밖 — 공개 웹 | 라우터가 L3 으로 판정했을 때 |
| `level-4.md` | 스레드 밖 · 회사 안 — 다른 채널·노션·지라·첨부 | 라우터가 L4 로 판정했을 때 |
| `level-5.md` | 개인 메신저. 미연결이라 표시만 한다 | 라우터가 L5 로 판정했을 때 |

각 레벨 파일은 **자기 안에서 완결한다.** 그 파일 하나만 열고도 그대로 행동할 수 있다.
그래서 파일 사이에 내용이 조금 겹친다. 겹치는 것을 없애려고 참조로 바꾸면 부르는 쪽이 결국
여러 파일을 열게 되고, 그것이 이 구조가 피하려는 상태다.

`router.md` 는 반대로 레벨 파일의 내용을 **다시 적지 않는다.** 적으면 같은 사실이 두 곳에
살고 두 곳이 갈라진다.

## 이 폴더의 축은 L0~L5 컨텍스트 레벨 하나뿐이다

여기서 말하는 레벨은 **컨텍스트 분석 레벨**이다. "정확한 답을 내려면 얼마나 깊이 읽어야
하는가"를 재고, 사전에 정해져서 무엇을 읽을지를 가른다. 정의 원본은
`docs/slack-context-analysis-levels.md:216-353` 에 있다.

이 데몬에는 다른 등급 체계가 다섯 더 돈다. **숫자를 섞어 쓰지 않는다**
(`docs/slack-ack-two-axis-design.md:278-305` 의 등록부 규칙).

| 기호 | 무엇을 재나 | 이 폴더와의 관계 |
|---|---|---|
| `L0`~`L5` | **컨텍스트 깊이 — 얼마나 읽을 것인가** | **이 폴더의 축** |
| `R0`~`R4` | 응답 코스트 — 얼마나 적게 내보낼 것인가 | 다른 축. `emoji-layer.mjs` 의 `responseGrade()` |
| `F0`~`F3` | 문제 정의 — 물음이 제대로 세워졌나 | 다른 축. `problem-frame.mjs` |
| `E2`~`E4` | 근거 영수증 — 실제로 무엇이 붙었나 (`requestLevel`) | 다른 축. **사후**에 적힌다 |
| `C0`~`C2` | 컨텍스트 수집 — 사람을 몇 명 조회했나 | 다른 축 |
| `1`~`9` | 열람 권한 (`slack-permission-policy.json`) | 다른 축. 사람별로 붙는다 |

`L2` 와 `R2` 와 `F2` 는 아무 관계가 없다. 원장에 적을 때 숫자만 쓰지 말고 언제나 기호를
앞에 붙인다.

**레벨은 입력 깊이를 정하고 출력 모양을 정하지 않는다.** 2026-08-31 에 "근거 깊이가 응답
코스트를 정하던 연결"을 의도적으로 끊었다(`docs/slack-ack-two-axis-design.md:290-292`).
그 연결을 여기서 되살리지 않는다.

## 가정 — 조사해도 답이 안 나와서 정하고 간 것

이 다섯은 근거가 아니라 판단이다. 나중에 뒤집힐 수 있으므로 어디를 고쳐야 하는지까지 적는다.

- **G1.** 라이언 구술의 "레벨1·2·3·5"에서 L0·L4 가 빠진 것은 구술 누락으로 본다.
  L0 과 L4 는 코드와 문서에 실재한다(`slack-context-analysis-levels.md:220`, `:288`).
- **G2.** "manifest.end" 는 인식 오류로 보고 `manifest.md` 로 정한다.
- **G3.** 보는 중 이모지의 기본값은 `mag`(🔍). 👀 는 수집 트리거라 코드가 거부한다.
  라이언이 결정 카드에서 다른 값을 고르면 JSON 한 줄로 바뀐다.
- **G4.** `decision` 판정은 결정적 규칙(veto·어휘집)만 쓴다. 모델을 새로 부르지 않는다.
  근거 없이 판정을 세우는 것보다 "모른다(unknown)"를 보는 중으로 보내는 쪽이 싸다.
- **G5.** 이번 배치는 레벨별 **정책 문서**와 **이모지 동작**만 만든다. L0~L5 를
  데몬 코드가 실제로 분기하게 만드는 것(`needLevel`/`usedLevel` 필드 신설)은
  `slack-context-analysis-levels.md` 가 소유한 별도 배치이고 여기서 하지 않는다.

G5 때문에 지금 이 폴더는 **사람과 모델이 읽는 정본**이고, 데몬이 코드로 분기하는 자리는
아직 아니다. 데몬에 실제로 반영된 것은 이모지 축 하나뿐이다(`slack-emoji-layer.json` 의
`decision`·`resolves`). 그 둘이 어긋나면 이 파일이 아니라 JSON 이 이긴다 — 도는 것이 정본이다.

## 이 폴더가 정하지 않는 것

- **나가는 글의 모양.** 레벨은 `renderReply` 에 닿지 않는다.
- **글이냐 리액션이냐.** 그것은 `R` 축(`emoji-layer.mjs` 의 `responseGrade()`)이 정한다.
- **누구에게 답하지 않을 것인가.** 그것은 공용 레이어(`~/.must-aios/sources/docs/slack-layers/`)와
  이 폴더 옆의 `slack-reply-policy.json`(채널·사람별 `no-reply`)이 정한다. 공용 레이어의
  README 가 "이 폴더에는 레이어만 있다. 레벨은 여기 없다. 레벨은 프로젝트가 정한다"고
  명시하고, 이 폴더가 그 "프로젝트가 정하는 자리"다.

  **이름이 닮았지만 다른 파일이다.** `slack-reply-policy.json` 은 **발신 대상** 축이고
  (누구에게 보내지 않는가), 이 `reply-policy/` 폴더는 **컨텍스트 깊이** 축이다
  (얼마나 읽는가). 둘을 합치지 않는다.
- **자격증명·급여·민감 정보 요청의 처리.** `security-gate.mjs` 가 이 폴더보다 먼저 선다.
