# cm-question 규약 — 골 메신저의 박스형 명확화 질문

골 페이지 우측 메신저에서 AI가 사용자에게 "명확화 질문"을 던질 때, 길게 늘어선
마크다운 불릿 대신 **한 번에 하나씩 보여주는 박스 카드**로 렌더한다. 이를 위해
AI는 질문을 자유 형식 마크다운이 아니라 약속된 코드블록으로만 출력하고,
프론트엔드가 그 블록을 인터랙티브 카드로 변환한다.

## 왜 필요한가

- 좁은 메신저 폭(약 380px)에 Q1·Q2·Q3가 한꺼번에 세로로 쌓이면 스크롤이 길어지고
  가독성이 떨어진다. 사용자는 답을 미룬다.
- `goal-policy.md`의 메신저 목적은 "대화로 목표를 또렷하게 만드는 것"이다. 한 번에
  한 질문만 보여주고, 추천 답안과 직접 입력을 함께 주면 응답 비용이 낮아진다.

## 출력 형식 (AI가 지키는 약속)

AI는 명확화 질문을 낼 때, 본문 마크다운으로 풀어쓰지 말고 cm-question 으로 태그된
코드블록 하나로만 출력한다. 블록 앞에는 짧은 맥락 한두 줄을 둘 수 있다.

블록 내부는 JSON이며 최상위에 q 배열을 둔다. 각 원소가 질문 하나다.

```cm-question
{"q":[
  {"ask":"goal-01의 본질은 무엇인가요?","opts":[
    {"label":"끝난 작업을 정리·기록","why":"제목의 '정리'와 부합","rec":true},
    {"label":"진행 중 지급 운영 관리"}
  ]},
  {"ask":"\"26번의 지급\"의 의미는?","opts":[
    {"label":"task 번호와 1:1"},
    {"label":"실제 송금 약 26건"}
  ]}
]}
```

필드 의미는 다음과 같다.

- ask: 질문 한 줄. 짧고 또렷하게.
- opts: 선택지 배열. 한 질문당 2개에서 4개.
  - label: 선택지 요약. 짧게.
  - why: 선택지를 추천하는 한 줄 근거. 추천 선택지에만 단다.
  - rec: 추천 여부. 한 질문에서 가장 가능성 높은 선택지 하나에만 true.

## 규칙

- 물어볼 질문을 q 배열에 모두 담는다. 프론트엔드가 하나씩 순서대로 보여준다.
- 각 질문에서 추천은 정확히 하나(rec true)만 둔다. 그 선택지에만 why를 붙인다.
- label은 짧게 쓴다. 사용자는 직접 입력으로도 답할 수 있으므로 모든 경우를
  선택지로 나열할 필요는 없다.
- 질문이 아니라 일반 설명이나 답변일 때는 평소대로 마크다운으로 답한다. cm-question
  블록은 사용자에게 물어볼 것이 있을 때만 쓴다.

## 렌더링 동작 (프론트엔드)

구현 위치는 두 곳이며 같은 규약과 카드 모양을 쓴다.

- 골 페이지 우측 메신저: AppDelegate.swift (extractQ / renderAssistant / buildQcard)
- 목표 추가 페이지의 인라인 세션 뷰: GoalAddContent.swift (gsExtractQ / gsRenderAssistant /
  gsBuildQcard) — 전송만 세션 뷰의 gsUser / gsPost 경로를 쓴다.

- extractQ: 어시스턴트 텍스트에서 cm-question 블록을 떼어내 JSON으로 파싱한다.
  파싱에 실패하면 질문 카드 없이 원문을 그대로 마크다운으로 렌더한다(안전한 폴백).
- renderAssistant: 블록을 뺀 나머지 텍스트는 마크다운으로 렌더하고, 질문이 있으면
  그 아래에 카드를 붙인다. 히스토리 로드와 실시간 done 양쪽에서 같은 함수를 쓴다.
- buildQcard: q 배열을 받아 한 번에 하나씩 그린다. 진행 표시(현재/전체), 질문,
  추천 강조(파란 테두리와 추천 배지), 나머지 선택지, 직접 입력칸, 다음 질문 귀띔으로
  구성한다. 선택지를 누르거나 직접 입력을 보내면 그 답을 기록하고 다음 질문으로
  넘어간다. 마지막 질문까지 답하면 모든 답을 한 메시지로 합쳐 한 턴으로 전송한다.
- 스트리밍 중에는 raw JSON이 보이지 않도록, 블록 시작이 감지되면 본문 대신
  "질문 준비 중…" 힌트를 표시한다. 블록은 턴 종료(done) 시 카드로 바뀐다.

## 전송 형식

사용자가 모든 질문에 답하면, 각 질문과 답을 번호로 묶은 한 줄씩의 텍스트를
기존 경로 POST /api/goal/chat2/say 로 한 턴에 보낸다. 답하지 않고 넘어간 질문은
"(미응답)"으로 표기한다. 별도 라우트나 프로토콜 변경은 없다.
