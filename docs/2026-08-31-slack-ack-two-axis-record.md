# 2026-08-31 슬랙 자동 응답 두 축 개편 — 무엇을 어떻게 고쳤나

세션 레벨 L1 (사람 확인 없이 끝까지). 예외는 하나였다 — 슬랙으로 실제 발신하지 않는 것.
그 예외는 지켰다. **이 작업 중 슬랙으로 나간 것은 없고, 데몬도 재시작하지 않았다.**

설계는 `slack-ack-two-axis-design.md` 에 있다. 이 문서는 그 설계가 코드로 어떻게 옮겨졌고
무엇이 남았는지의 기록이다.

---

## 1. 시작점 — 무엇이 잘못 나갔나

Maryam Mansha 가 스레드에서 Hamilton Ude 에게 "첨부 PDF 다운받아 서명해서 여기로 다시
올려주면 된다, 별도 e-서명 링크 필요 없다"고 이미 명확히 안내했다. 거기에 라이언 계정으로
자동 응답이 나갔다.

```
@Maryam Mansha This is an automated agent response. It should still be very helpful.
Purpose: Provide instructions to Hamilton Ude on how to sign and return the PIP notice document.
Answer: Instruct Hamilton Ude to download the attached PDF, add a signature, and send the signed copy back in the channel.
```

이미 나온 답의 재진술이다. 나갔어야 할 것은 경례 이모지 하나뿐이었다.

**이것은 답변 품질의 문제가 아니라 발신 여부의 문제다.** 그 구분이 이번 개편 전체의 축이다.

같은 날 두 건이 더 있었다. 티타임 공지("See you all at tea break soon.")에 원문 재진술이
나갔고, Piyush DM 에는 다른 주제의 채널 컨텍스트가 근거로 딸려 들어가 엉뚱한 법인명이
실린 답이 나갔다 (원인 조사: `lion-os/docs/2026-08-31-slack-misfire-piyush-dm-investigation.md`).

---

## 2. 진단 — 축이 하나뿐이었다

코드를 읽고 나온 진짜 원인은 서두 문구가 아니었다.

`evidenceRequestLevel()` 이 재는 것은 **근거를 얼마나 모았는가**인데, 그 값이 그대로
**글을 얼마나 쓸 것인가**를 정하고 있었다. 첨부가 하나만 있어도 레벨 4가 되고, 레벨 4
렌더러는 직답 줄(`Answer:`)을 **아예 내지 않고** 보고서 포맷을 강제했다.

> 근거를 많이 모을수록 글이 길어지고 답은 사라지는 구조였다.
> 첨부를 붙여 물을수록 답이 없어진다.

그리고 이모지 판정의 기본값이 거꾸로였다. `quickVerdict()` 가 좁은 어휘집에 걸릴 때만
이모지를 달고, `null` 이 "글로 답하라"는 뜻이었다. 어휘집은 닫는 말의 화이트리스트라
**닫는 말도 아니고 묻는 말도 아닌 메시지는 전부 글로 떨어졌다.** 티타임 공지가 통과한
이유가 "글로 답할 이유가 있어서"가 아니라 "정규식에 안 걸려서"였다.

## 3. 고친 것

### 3-1. 두 축을 세웠다

| 축 | 기호 | 무엇을 판정하나 | 성격 |
|---|---|---|---|
| 축 1 커뮤니케이션 코스트 | `R0`~`R4` | 이 메시지가 글을 받을 자격이 있나 | **덜** 내보내는 쪽 |
| 축 2 문제 정의 | `F0`~`F3` | 물음이 제대로 세워졌나 | 근거가 있을 때만 **더** 내보내는 쪽 |

판정에는 두 태그가 **항상 함께** 붙는다. 두 축이 만나는 지점은 하나뿐이다 —
`F2`(이미 답이 나와 있다)가 축 1을 `R1` 로 강등한다.

### 3-2. 기본 분기를 뒤집었다

`emoji-layer.mjs` 에 `responseGrade()` 를 넣고 **바닥값을 `R1`(리액션 하나)** 로 했다.
판정이 서지 않으면 `R1` 이다. 모르면 이모지다.

기존 veto 패턴(물음표·요청 신호)은 더 이상 "글로 보내라"가 아니라 **`R2` 이상 후보**일
뿐이다. 후보가 된 뒤에도 신규성 게이트를 통과해야 실제로 글이 된다.

강등할 때 **달 이모지를 함께 들려 보낸다.** 이것이 없으면 Maryam 건에서 글도 안 나가고
리액션도 안 나가는 침묵이 된다.

### 3-3. 신규성 게이트 — 이번 개편의 핵심 방어

`novelty-gate.mjs` (신규). 후보 글의 실질이 스레드에 이미 있으면 막는다. 특히 **질문 이후에
나온 메시지**를 본다. `ackSendGate` 의 한 항목(`NO_NOVELTY`)으로 들어갔다.

어형을 접두사로 맞추는 것(sign / signed / signature)이 결정적이었다. 그것 없이는
Maryam 건이 임계값 아래로 떨어져 그대로 나간다.

모델이 "무엇을 더하는지" 한 줄을 대지 못하면 자동으로 `R1` 로 내려간다(`NO_ADDS_LINE`).

### 3-4. 정형 서두와 라벨 틀을 전부 지웠다

- `This is an automated agent response. It should still be very helpful.` 와 한국어 판
- `This is an agent answer for now. A final decision will follow shortly.` 와 한국어 판
- `Purpose:` `Answer:` `Naming:` `Intent ·` `Alignment:` `Define problem:`
  `Internal evidence:` `Requirements:` `Sufficiency:` `Recommendation:` `Read as:` 라벨 전부
- `noBasisText`("답변 불가 / 이유: / 필요:") — 그것도 라벨 틀이다. 이제 근거를 못 찾으면
  글이 아니라 `R1` 로 내려간다
- `legacyPrompt` 80줄 통째로 삭제. 이미 안 도는 코드였지만 옛 틀의 정본처럼 남아 있어서
  다음 사람이 그것을 보고 되살린다

`renderAcknowledgement` 와 `renderAcknowledgementV2` 를 **삭제**했다. 둘 다 작성자가 아니라
**직렬화기**였다 — 라벨 칸을 만들어 놓고 모델에게 채우게 하는 구조. 빈 칸을 남기지 않으려고
모델이 이미 아는 말을 다시 적는다. Maryam 건의 `Purpose:` 줄이 정확히 그렇게 만들어졌다.

이제 렌더러는 `renderReply` 하나이고, 모델이 쓴 문장을 다듬어 낼 뿐이다. 그리고 모델이
라벨을 뱉어도 `stripFrames` 가 걷어낸다 — **두 겹으로 막았다.**

### 3-5. 근거 깊이와 응답 분량을 끊었다

`renderReply` 는 이제 `requestLevel` 을 **인자로 받지 않는다.** 첨부가 있어 근거 깊이가
L4 가 되어도 직답이 그대로 나간다. `evidenceRequestLevel` 은 계속 계산되지만 원장에만
남는다.

### 3-6. 축 2 — 근거를 가져오고, 못 가져오면 침묵한다

`problem-frame.mjs` (신규). `F3` 판정이 서면 젠스파크 CLI(`gsk`)로 실제 웹 자료를 조회해
세 줄짜리 재정의를 낸다. 답은 쓰지 않는다.

**조회 실패·시간 초과·빈손이면 침묵한다.** 근거 없는 훈수는 그 자체로 커뮤니케이션
코스트이기 때문이다. 세 줄 규격을 못 채운 `F3` 은 `F0` 로 내린다.

`gsk` 의 `--timeout` 기본값이 **30분**이라 그대로 두면 데몬이 매달린다. `--timeout 20000`
명시 + `execFile` 20+4초 + `SIGKILL` 로 두 겹을 걸었다.

에이전트 정의(`.claude/agents/lion-condition-mate-worker-slack-problem-framing.md`)에서는
**`WebSearch` 와 `WebFetch` 를 일부러 뺐다.** 조회가 실패했을 때 다른 경로로 조용히 갈아탈
수 있으면 "실패하면 침묵"이 규칙이 아니라 권고가 된다. 도구 목록으로 규칙을 집행한 것이다.

### 3-7. 출력을 두 층으로 갈랐다

슬랙에 나가는 것은 **2줄 · 280자** 상한이다. 넘으면 **잘라내지 않는다** — 들어가는 문장만
남기고 나머지는 통째로 MD 로 간다. 잘린 문장을 슬랙에 남기는 것은 요약이 아니라 훼손이다.

MD 는 두 곳에 남는다. 새 관행을 만들지 않고 있는 것 두 개를 그대로 썼다.
- 디스크: `~/.condition-mate/slack-translate/ack-notes/<channel>-<ts>.md` (`OUT_DIR` 관행)
- 슬랙 스레드에 파일 업로드 (`files.getUploadURLExternal` → `completeUploadExternal`)

**스코프는 이미 있었다** — `cm-slack-user-token` 의 `x-oauth-scopes` 에 `files:write` 가
들어 있는 것을 확인했다. 새 권한도 새 인증도 필요 없다. 받는 사람은 이 맥 바깥이라
저장소 경로도 127.0.0.1 대시보드도 도달하지 않고, 스레드 파일만 도달한다.

### 3-8. 언어 — 스레드의 원래 언어

원문 → 스레드 컨텍스트 → 프로필 국가 순으로 정한다. 예전엔 판정이 안 서면 곧바로
**보내는 사람의 프로필 국가**로 떨어졌다. 그것은 스레드의 언어가 아니다.

### 3-9. 채널 컨텍스트를 근거로 승격하지 않는다

`resolveAccess` 에 `messageOnly = true` 기본값. Piyush 건에서 엉뚱한 법인명이 넘어온
경로가 이것이었다(재현 20/20 이 전부 채널 컨텍스트 때문이었다).

### 3-10. 원장

`items.jsonl` 새 **선택** 필드 6개: `ackGrade` `ackGradeReason` `frameGrade` `frameReason`
`ackNoteFile` `ackNoteUploaded`. `actions-daemon.jsonl` 에 `ack.grade` · `ack.frame` 추가.

왜 글이 안 나갔는지가 보이지 않으면 "왜 답이 없지"가 다시 사람의 일이 된다.

## 5. 검증 — 실제로 돌린 것

발신 없이 순수 함수와 스텁으로 돌렸다. 상위 세션이 워커 보고를 받은 뒤 **직접 다시 돌려
확인**했다.

```
== A. Maryam 건 ==
  ok  chat.postMessage 가 한 번도 불리지 않는다   []
  ok  리액션 하나로 끝난다                        :white_check_mark:
  ok  왜 강등됐는지가 원장에 남는다
      ack.blocked: NO_NOVELTY:ALREADY_ANSWERED_AFTER:0.833 · 확신 0.95
      ack.grade:   R1 강등 · 스레드에 이미 있음 · 중복 0.833
== B. 티타임 공지 ==  ok  글 없이 리액션 하나
== C. 진짜 질문 ==    ok  1회 발신 · 서두·라벨 없음 · 146자 · 전문은 MD
== D. F2 강등 ==      ok  {"ackGrade":"R1","frameGrade":"F2"} 두 태그가 함께
== E. adds 빔 ==      ok  R1 강등 · NO_ADDS_LINE
== F. 긴 답 ==        ok  본문 174자 / MD 656자
== G. 자격증명 ==     ok  토큰 모양 없음 · 키체인 이름 없음
```

그 밖에: 순수 함수 38건 통과. **옛 `items.jsonl` 1554건 전부 파싱**, 새 필드가 옛 줄에
하나도 없고 기본값으로 전부 읽힘. `node --check` 11개 모듈 전부 통과. 정책 JSON 2개
파싱 통과. 슬랙 e2e 12개 exit=0.

`gsk` 조회는 실제로 한 번 돌렸다(슬랙 아님, 읽기만): 1881ms, 3행 반환.

## 6. 남은 것 — 라이언이 정할 것

### 6-1. ⚠️ 이 폴더의 데몬 모듈이 거의 다 git 에 없다

`git ls-files Sources/Plugins/Slack/Daemon/` 결과 **추적되는 파일이 둘뿐이다** —
`slack-eyes-daemon.mjs` 와 plist.

`alignment-engine.mjs` · `emoji-layer.mjs` · `answer-context.mjs` · 정책 JSON 전부 ·
오늘 만든 새 모듈 전부가 **untracked** 다. `.gitignore` 때문이 아니라
(`git check-ignore` 결과 "not ignored") 그냥 `git add` 된 적이 없다. 플러그인을
`Sources/Plugins/` 아래로 옮긴 커밋(`a5b03d1`)에서 둘만 따라간 것으로 보인다.

**오늘 한 작업의 대부분이 버전 관리 밖에 있다.** `git clean` 한 번이면 사라진다.
커밋은 라이언의 몫이라 하지 않았다.

### 6-2. 신규성 임계값 — 전수 조사로 0.65 로 내렸다

구현 워커가 "0.7 은 표본 두 개 사이에서 내가 고른 값"이라고 정직하게 보고했고, 코퍼스
전수 조사를 따로 돌렸다. 결과는 §9 에 따로 적었다. **0.65 로 내렸고, 그 값도 분포가
시킨 것이 아니라 사람이 고른 것이다** — 다만 이번에는 고른 자리 양쪽에 무엇이 있는지
세어 놓고 골랐다.

### 6-3. 고친 것과 도는 것이 아직 다르다

```
도는 프로세스  PID 86761 · 기동 Sun Aug 30 17:26:20
설치본         /Applications/ConditionMate.app/Contents/Resources/ · Aug 31 13:39
저장소 원본    Sources/Plugins/Slack/Daemon/ · Aug 31 14:2x~
```

세 겹이 전부 어긋나 있다. 오늘 들어간 것은 **하나도 살아 있지 않다.**
재빌드 → 설치본 교체 → `launchctl kickstart` 가 있어야 한다.

`Scripts/build-app.sh` 는 고쳐 두었다. `send-layer.mjs` · `novelty-gate.mjs` ·
`ack-note.mjs` 는 **정적 import** 라 번들에서 빠지면 폴백이 아니라 **데몬이 아예 안 뜬다.**
번들 복사 목록에 넣지 않고 빌드하면 그 자리에서 죽는다.

### 6-4. 행동이 크게 바뀐다

1:1 멘션에서 묻지도 요청하지도 않은 메시지는 이제 **전부 리액션 하나**다. 설계가 시킨
것이지만, 뒤집기 전에는 그런 자리가 전부 글이었다. 배포 직후 며칠은 "왜 답이 없지"가
아니라 "왜 이모지만 있지"가 보일 것이다. 사유는 전부 원장에 남는다.

### 6-5. 되돌릴 수 있는 판단 두 개

- **슬랙 본문에 파일 참조 줄을 안 붙였다.** "자세한 내용은 첨부 참고" 부류가 설계 §7-1 이
  금지한 이음말이기 때문이다. MD 를 그 스레드에 올려 파일 자체가 참조가 되게 했다.
  업로드가 실패해도 없는 파일을 가리키는 문장이 남지 않는다.
- **스레드에 올리는 MD 를 디스크 판과 갈랐다.** 업로드 판에서 Jira · 다른 스레드 검색
  결과 · 용어집 · 첨부 원문을 뺐다. 근거를 붙이려고 다른 대화를 이 방으로 옮기는 것이
  바로 Piyush 건의 모양이기 때문이다. 디스크 판은 전부 담는다.

## 7. 하지 않은 것

- **슬랙으로 아무것도 보내지 않았다.** `chat.postMessage` · `reactions.add` ·
  `files.*` 쓰기는 전부 스텁으로만 돌렸다.
- 데몬을 재시작하지 않았고 앱을 재빌드하지 않았다.
- `git commit` 하지 않았다.
- 축 2 의 `F3` 판정 프롬프트를 실제 메시지에 대고 돌려 보지 못했다(파싱·폴백 경로만).

## 8. 같은 폴더를 두 세션이 동시에 고쳤다

작업 중 다른 세션이 같은 폴더를 쓰고 있었다. `send-layer.mjs` ·
`slack-sensitive-policy.json` · 그 시험 두 개가 그쪽 산출물이다.

되돌린 것은 없다. 그쪽이 넣은 `scaffoldLeaks` · `sensitiveContext` · `echoRatio` ·
`patternVeto` 는 전부 살아 있고 그 위에 쌓았다.

**겹치는 것이 하나 있다.** 그쪽의 `echoRatio` 와 이쪽의 신규성 게이트가 같은 것을 잰다.
그쪽은 "측정만 하고 차단하지 않는다"고 명시했고(실측값이 임계를 놓을 만큼 안 갈린다는
근거까지 적어 두었다), 이쪽은 실제로 막는다. **둘 다 남겼다** — `echoRatio` 는 원문 한 건
대비 측정값으로 원장에 계속 쌓이고, `NO_NOVELTY` 는 스레드 전체·이후 메시지 대비로 막는다.
차이는 어형 정규화이고, 그것 없이는 Maryam 건이 임계값 아래로 떨어진다.

앞으로 이 폴더를 고칠 때는 두 세션이 동시에 들어가지 않게 하는 편이 낫다. 이번에는
편집 직전 재확인으로 넘겼지만, 그것은 절차가 아니라 운이다.

## 9. 신규성 임계값 전수 조사 (같은 날, 별도 조사)

`novelty-gate.mjs` 를 그대로 import 해서 과거 ack 을 전수 계산했다. 프로덕션 코드는 한 줄도
고치지 않았고 슬랙은 읽기 메서드만 불렀다.

### 9-1. 잰 것

| 항목 | 값 |
|---|---|
| `ackTs` 가 있는 건(글이 실제로 나갔다) | 72 |
| `ackAt` 만 있는 건(R1 이모지, 글 아님) | 7 |
| **overlap 계산 가능** | **48** |
| 본문이 슬랙에서 삭제되어 계산 불가 | 23 |

분포: `min 0 · median 0.255 · Q3 0.466 · p90 0.635 · max 0.818`

**재현 확인:** 사고 본문을 같은 파이프라인에 넣으면 `0.833 / ALREADY_IN_THREAD` 가 나온다.
구현 워커가 보고한 값과 소수점까지 일치한다 — 재현부가 맞다는 뜻이다.

### 9-2. 갈라지는 자리는 없다

가장 큰 간격은 0.081(0.645→0.726). 눈으로는 골짜기로 보이지만, 같은 범위에서 균일하게
48개를 뽑으면 이만큼 벌어지는 일이 **29.1%** 확률로 일어난다(몬테카를로 20만 회).
표본이 적어 난 구멍과 구분되지 않는다.

> **어떤 값을 골라도 그것은 분포가 시킨 것이 아니라 사람이 고른 것이다.**

### 9-3. 0.7 로 막혔을 4건 — 전부 정당한 차단

`0.818` 상대가 쓴 한 문장을 `Purpose` 줄과 `Answer` 줄로 두 번 다시 쓴 것 ·
`0.806` 낱말 순서만 바꾼 재진술 · `0.727` 상대 글을 라벨 다섯 개로 나눠 담은 것 ·
`0.726` Maryam 자신의 메시지를 그대로 되돌려 준 것(8/31 사고와 같은 부류).

**넷 다 새 사실 0. 오탐 0건.**

### 9-4. 왜 이 코퍼스로는 임계값을 정할 수 없나 — 세 가지

**(1) 코퍼스의 88%는 지금 파이프라인이 만들 수 없는 글이다.** 48건에 `scaffoldLeaks()` 를
돌리면 42건이 발신 레이어에서 먼저 죽는다(옛 v1 라벨 포맷). 신규성 게이트가 판정할 기회가
있는 것은 6건이고 그중 4건은 정형 문구다. **오늘의 포맷에서 실측 표본은 사실상 2건이다.**

**(2) 옛 포맷의 고정 문자열이 overlap 을 아래로 끌어내리고 있었다.** `automated agent
response … purpose … alignment` 는 스레드에 있을 리 없어 언제나 "새 토큰"으로 세어져
분모를 키웠다. 지금은 `stripFrames` 가 그것을 지운 뒤 게이트에 넣는다.

| 본문 모양 | median | p90 | max | t=0.7 차단 |
|---|---|---|---|---|
| A. 나간 그대로 (옛 v1) | 0.255 | 0.635 | 0.818 | 4 / 48 |
| **B. `stripFrames` (지금 게이트가 보는 모양)** | **0.289** | **0.742** | **1.0** | **6 / 47** |
| C. `slackBrief` (지금 슬랙에 나가는 두 줄) | 0.5 | 0.816 | 1.0 | 10 / 45 |

**A 위에서 고른 0.7 은 B 위에서는 0.7 이 아니다.** 옛 원장 값과 새 값을 그냥 비교하면 틀린다.

**(3) 코퍼스에 "좋은 답"이 한 건도 없다.** 48건 전문을 다 읽었고, 스레드에 없던 사실·수치·
날짜·이름을 하나라도 더한 ack 은 **0건**이다. overlap 이 낮은 것들은 새 것을 더해서 낮은
것이 아니라 말이 길거나 **언어가 달라서** 낮다.

> 정답 라벨이 하나도 없으므로 이 코퍼스로 임계값을 최적화하면 최적값은 0 으로 수렴한다 —
> 전부 막는 것이 정답이 된다. 그것이 "게이트가 아니라 스위치"다.

### 9-5. 알려진 사각지대 — 한국어 되풀이

`overlapRatio` 는 낱말을 겹쳐 보므로 **한국어로 옮긴 되풀이는 구조적으로 잡히지 않는다.**

```
같은 언어 n=39 · median 0.311 · ≥0.7  6건
다른 언어 n=8  · median 0.213 · ≥0.7  0건
```

새 사실을 더해서 낮은 것이 아니라 낱말이 안 겹쳐서 낮다. **8/31 사고가 잡힌 것은 영문–영문
이었기 때문이다.** n=8 이라 확정은 아니어서 고치지 않았고, 알려진 한계로만 기록했다.
지금 표본으로 손대면 또 지어내는 것이 된다.

### 9-6. 원장과의 대조 — 어긋난 곳 셋

**(가) `ackTs` 는 있는데 원장 `ack` 행이 없는 건 5.** `postSecurityBlocked()` 와
`postLevelOneRoute()` 가 발신은 하고 `act('security.block')`/`act('route.level1')` 로
남기기 때문이다. **원장의 `ack` 행 수(67)를 발신 건수(72)로 읽으면 안 된다.**

**(나) 신규성 게이트는 프로덕션에서 한 번도 돈 적이 없다.** `NO_NOVELTY` 0행, `ack.grade`
0행. 도는 프로세스가 게이트 파일보다 **2분 먼저** 떴다.

**(다) 그리고 앞으로도 근거가 쌓이지 않는 구조였다.** 성공 경로 `act('ack', …)` 에
overlap 이 안 들어가고 `ack.blocked` 에만 남는다 — **막힌 건의 값만 쌓이고 통과한 건의
값은 버려진다.** 임계값을 다시 정하려면 정확히 통과한 쪽이 필요한데 그쪽만 없다.
이것을 고치는 것이 조사에서 나온 유일한 코드 권고였고, 반영했다.

### 9-7. 그래서 무엇을 더 모아야 정할 수 있나

1. **성공한 ack 에도 overlap 을 남긴다** (반영 완료).
2. **오늘 포맷으로 나간 ack 30건 이상.** 게이트를 켜기 전 며칠 `overlapMax` 를 1.1 로 두어
   아무것도 막지 않으면서 값만 쌓는 방법이 있다.
3. **"이 답은 새 것을 더했다"는 사람 판정.** 나간 답에 👍/👎 하나면 라벨이 된다. 30건이면
   오탐이 시작되는 자리를 처음으로 잴 수 있다.
4. **한국어 되풀이 표본.** 지금 8건뿐이고 전부 0.7 아래다. 그쪽 표본이 없으면 게이트를
   켜도 절반은 무방비다.
