# goal-102: 버그 헌트가 한 번만 돌고 멈춤 — 토글 '켜짐'이 헌트를 (재)시작하지 못한다

- 상태: backlog
- 목적: 버그 헌트는 퇴근 시 손으로 한 번 실행하면 4시간 동안 라운드를 반복해야 하는데, 첫 세션이 끝나거나(또는 중단되면) 다시는 돌지 않는다. 대시보드 토글을 '켜짐'으로 되돌려도 행(row)만 켜진 것으로 보일 뿐 실제 헌트 프로세스를 재실행하지 않는다. 즉 토글 ON이 헌트를 시작/재시작하는 동작과 연결되어 있지 않아, 사용자가 보기에 "한 번만 작동하고 마는" 상태가 된다.
- 작성일: 2026-06-26
- 관련 코드: Sources/ConditionManager/AppDelegate.swift:2007-2024 (/api/worker/toggle), :2031-2037 (/api/worker/run — qa-agent 전용), :242-245 (bug-hunt 등록), :281-283 (bugHuntDisabledFlag); Sources/ConditionManager/Core/WorkerRegistry.swift:164-169 (toggleable/runnable/manual 판정); Scripts/bug-hunt.sh (포그라운드 수동 러너, launchd 없음); Scripts/com.condition-manager.qa-agent.plist (qa-agent만 스케줄러 존재)

## 1. 증상 / 재현

재현 절차:
1. 퇴근 시 `Scripts/bug-hunt.sh` 를 손으로 실행한다 (기본 4시간, 1200초 라운드 주기).
2. 라운드 1이 돌아 신규 goal 1건이 작성된다 (예: 2026-06-25 04:02:31 goal-58 생성).
3. 다음 라운드를 기다리는 도중 헌트를 멈춘다 — 대시보드에서 '꺼짐' 토글을 누르거나, stop 플래그가 잡히거나, 4시간 윈도가 끝난다.
4. 잠시 후 대시보드에서 버그 헌트 토글을 다시 '켜짐'으로 되돌린다.

기대 동작:
- 토글을 '켜짐'으로 되돌리면 버그 헌트가 다시 시작되어, 남은 시간 동안 1200초 주기로 라운드를 계속 돌려야 한다. 적어도 사용자가 한 번 켜 두면 라운드가 반복적으로 실행되어야 한다.

실제 동작:
- 토글을 '켜짐'으로 되돌려도 헌트는 다시 돌지 않는다. 워커 상태 행은 '켜짐'으로 표시되지만 실제로 도는 `bug-hunt.sh` 프로세스는 없어, 새 라운드도 신규 goal도 더 이상 생기지 않는다.
- 워커 로그 기준 실제 흐름: 03:58:21 시작 → 04:02:31 라운드 1(goal 1건) → 04:03:01 중단/종료 이후로 라운드가 한 번도 더 실행되지 않음. 06:10:54 '켜짐' 토글도 로그 한 줄만 남길 뿐 헌트를 살리지 못한다. 사용자 체감: "한 번만 작동하고 말았어."

## 2. 원인 분석

버그 헌트에는 'UI에서 (재)시작하는 경로'가 아예 없다. 토글은 비활성화 플래그만 만지고, 프로세스를 띄우는 부분이 빠져 있다.

- 토글 핸들러 `/api/worker/toggle`(AppDelegate.swift:2017-2023)는 enabled=true일 때 `bug-hunt-disabled` 플래그를 삭제하고 레지스트리를 enabled로 표시할 뿐, `Scripts/bug-hunt.sh` 를 spawn하지 않는다. 즉 '켜짐'은 "다음에 누가 헌트를 돌리면 막지 마라"는 의미일 뿐, "지금 헌트를 시작하라"가 아니다.
- 즉시 실행 경로 `/api/worker/run`(:2031-2037)은 `qa-agent`에만 반응한다. `WorkerRegistry`에서도 `runnable`은 `qa-agent` 한정(WorkerRegistry.swift:165)이라, 버그 헌트는 대시보드에서 강제 실행할 수단조차 없다.
- 스케줄러도 없다. qa-agent는 `com.condition-manager.qa-agent.plist` 로 launchd가 60초마다 깨워 주지만, bug-hunt는 대응 plist가 없고 `manual = (w.id == "bug-hunt")`(WorkerRegistry.swift:169)로 명시적으로 '수동' 처리된다. 러너 `bug-hunt.sh` 자체도 포그라운드 단발 프로세스라, 한 번 끝나면 자신을 되살리지 않는다.

결론: 헌트를 시작하는 유일한 길은 셸에서 손으로 `bug-hunt.sh` 를 실행하는 것뿐인데, 대시보드 토글은 그 시작 동작과 연결돼 있지 않다. 그래서 첫 수동 세션이 끝나면 토글을 켜도 다시 돌지 않는다.

## 3. 수용 기준

- 대시보드에서 버그 헌트를 '켜짐'으로 만들거나 '즉시 실행'하면 실제로 `bug-hunt.sh`(또는 동등한 헌트 세션)가 (재)시작되어, 윈도가 끝날 때까지 설정된 주기로 라운드가 반복 실행된다. 토글 ON 이후 두 번째 이후 라운드가 워커 로그에 실제로 남는다.
- 워커 상태 행의 '켜짐/꺼짐' 표시가 실제 헌트 실행 여부와 일치한다. '켜짐'인데 도는 프로세스가 없는 불일치 상태가 발생하지 않는다 (또는 행이 그 상태를 정확히 구분해 보여 준다).
- 회귀 방지: 이미 한 세션이 돌고 있을 때 토글/즉시 실행이 중복 프로세스를 띄우지 않는다(한 번에 하나의 헌트만). '꺼짐'은 기존대로 다음 라운드에서 헌트를 멈춘다.
- 설계 결정(수동 유지 vs 토글로 시작 vs 스케줄러 도입) 중 어느 쪽을 택하든, "사용자가 한 번 켜면 라운드가 반복된다"는 관찰 가능한 결과가 보장된다.
